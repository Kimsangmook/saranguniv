# 찬양팀 지각비 관리 서비스 기획서

## 1. 문서 개요

### 1.1 목적

찬양팀의 토요일 지각, 일요일 지각·결석, 사유 신청, 지각비 정산 및 납부 현황을 하나의 서비스에서 관리한다.

토요일에는 모임 장소 벽에 부착한 공용 QR을 지각자가 직접 스캔하여 도착 시각을 기록하고, 일요일에는 담당자가 팀원별 지각·결석 여부를 수동으로 기록한다. 관리자는 CMS에서 팀원과 기록을 관리하고 기간별 정산을 생성한다. 팀원들은 공개 통계·랭킹 페이지에서 누적 현황을 확인할 수 있다.

### 1.2 핵심 운영 원칙

- 토요일에 지각한 팀원만 벽면의 공용 QR을 스캔한다.
- QR을 스캔하면 지각 기록 페이지로 이동한다.
- 최초 접속 시에만 사용자 인증을 진행한다.
- 사용자 인증에는 Google OTP와 유사한 시간 만료형 6자리 숫자를 사용한다.
- 토요일 지각비는 찬양팀 규칙에 따라 계산한다.
- 일요일 지각과 결석은 각각 1회당 3,000원이다.
- 승인된 사유가 있는 사용자는 토요일 QR을 찍지 않으며, 일요일 체크 화면에서는 비활성화된다.
- 정산은 확정 전까지만 검토·수정할 수 있다.
- 확정된 정산은 수정하거나 재정산할 수 없다.
- 통계·랭킹 페이지는 로그인 없이 볼 수 있는 공개 영역으로 제공한다.

## 2. 사용자와 권한

### 2.1 찬양팀원

- 벽면 QR 스캔을 통한 토요일 지각 기록
- 최초 접속 시 사용자 인증
- 토·일요일 지각·결석 사유 제출
- 본인이 제출한 사유와 처리 상태 확인
- 공개 통계·랭킹 조회

### 2.2 일요일 출결 담당자

- 현역 찬양팀원 목록 조회
- 일요일 지각·결석 수동 기록
- 승인된 사유가 있는 팀원 확인

일요일 출결 담당자 기능을 관리자 권한에 포함할지, 별도의 제한된 담당자 권한으로 제공할지는 구현 단계에서 선택할 수 있다. 별도 권한을 제공할 경우 팀원 관리나 정산 기능에는 접근할 수 없어야 한다.

### 2.3 관리자

- 관리자 로그인
- 팀원 등록 및 활동 상태 관리
- 사용자별 OTP 확인 및 인증 초기화
- 토요일 QR 기록 조회 및 정산 전 오류 수정
- 일요일 지각·결석 기록 관리
- 지각·결석 사유 승인 및 반려
- 기간별 정산 생성
- 사람별 납부 완료 처리
- 통계·랭킹 데이터 확인
- 기본 지각비 정책 관리

## 4. 팀원 관리

### 4.1 팀원 정보

- 이름
- 파트
- 연락처 또는 내부 식별 정보
- 가입일
- 활동 상태
- OTP 비밀키
- 인증된 기기 수
- 비고

### 4.2 활동 상태

- 현역
- 군 복무
- 중보팀
- 휴식
- 졸업
- 탈퇴

사용자 인증 목록과 일요일 출결 체크 목록에는 기본적으로 `현역` 팀원만 표시한다. 활동을 중단한 팀원도 과거 기록과 정산 이력 보존을 위해 삭제하지 않고 상태만 변경한다.

활동 상태가 변경되어도 기존 출결 기록, 정산 내역 및 통계 데이터는 유지한다.

## 5. 사용자 최초 인증

### 5.1 인증 흐름

1. 관리자가 CMS에서 팀원을 등록한다.
2. 사용자가 벽면 QR을 스캔한다.
3. 서비스가 현재 브라우저의 인증 상태를 확인한다.
4. 미인증 브라우저라면 인증 페이지로 이동한다.
5. 현역 찬양팀원 목록에서 본인을 선택한다.
6. 관리자가 CMS의 사용자 상세 화면에서 현재 6자리 OTP를 확인한다.
7. 사용자가 전달받은 OTP를 입력한다.
8. OTP가 유효하면 서버가 브라우저 인증 토큰을 발급한다.
9. 인증을 시작하기 전의 지각 기록 페이지로 돌아간다.
10. 서버 도착 시각을 기준으로 토요일 지각 기록을 생성한다.

### 5.2 OTP 규칙

- 숫자 6자리
- 시간 기반 일회용 비밀번호 방식
- 기본 유효시간 30초
- 시간이 지나면 자동 만료
- 사용자마다 별도의 OTP 비밀키 사용
- CMS 사용자 상세 화면에 현재 OTP와 남은 유효시간 표시
- 연속 인증 실패 횟수 제한
- OTP 비밀키 재발급 가능

### 5.3 브라우저 인증 규칙

- 인증 성공 후 서버가 추측할 수 없는 장기 인증 토큰을 발급한다.
- OTP 원문이나 OTP 비밀키는 브라우저에 저장하지 않는다.
- 가능하면 로컬 스토리지 대신 `HttpOnly`, `Secure`, `SameSite` 속성이 적용된 쿠키를 사용한다.
- 기기 변경, 브라우저 데이터 삭제 또는 인증 해제 시 다시 OTP 인증을 진행한다.
- 사용자 화면에 `이 기기 인증 해제` 기능을 제공한다.
- 관리자는 CMS에서 사용자의 전체 브라우저 인증을 강제로 무효화할 수 있다.

## 6. 토요일 QR 지각 기록

### 6.1 QR 운영 방식

- 모임 장소 벽에 하나의 공용 QR을 부착한다.
- QR은 지각 기록 진입 URL을 가리킨다.
- 지각한 팀원만 QR을 스캔한다.
- 정상 도착자와 승인 사유가 있는 팀원은 QR을 스캔하지 않는다.
- QR 진입 페이지는 사용자 인증 상태를 확인한 뒤 지각 기록 페이지로 보낸다.

### 6.2 기록 흐름

```text
벽면 공용 QR 스캔
→ 지각 기록 진입 페이지
→ 브라우저 인증 상태 확인
→ 미인증이면 최초 사용자 인증
→ 지각 기록 페이지 이동
→ 서버 시각으로 토요일 도착 기록 생성
→ 기록 완료 결과 표시
```

### 6.3 기록 규칙

- 휴대전화 시간이 아닌 서버 수신 시각을 도착 시각으로 사용한다.
- 한 사용자에게 날짜별 토요일 기록은 하나만 생성한다.
- 같은 날 여러 번 접근하면 최초 도착 시각을 유지한다.
- 중복 접근 시 새로운 지각 기록을 만들지 않는다.
- 현역 상태가 아닌 사용자는 새로운 지각 기록을 만들 수 없다.
- 관리자는 정산에 포함되기 전까지만 오기록을 수정하거나 무효화할 수 있다.
- 기록 수정 시 수정 전 값, 수정자, 수정 시각 및 수정 사유를 감사 로그로 남긴다.

### 6.4 결과 화면

신규 기록인 경우:

```text
김찬양님
2026년 8월 15일 10시 42분
지각 기록이 완료되었습니다.
```

이미 기록된 경우:

```text
김찬양님은 오늘 10시 42분에 이미 기록되었습니다.
최초 기록 시간이 유지됩니다.
```

## 7. 토요일 지각비 규칙

### 7.1 기본 기준

- 기본 모임 시작 시각: `10:30`
- 10:30까지 도착하면 지각비 없음
- 10:31부터 지각비 부과

### 7.2 과금표

| 실제 도착 시각 | 과금 방식 |
|---|---:|
| 10:30까지 | 0원 |
| 10:31~10:40 | 전체 지각 시간 × 분당 100원 |
| 10:41~10:50 | 전체 지각 시간 × 분당 300원 |
| 10:51~11:00 | 전체 지각 시간 × 분당 500원 |
| 11:01 이후 | 전체 지각 시간 × 분당 1,000원 |

### 7.3 계산 원칙

각 구간의 금액을 누진 합산하지 않는다. 실제 도착 시각이 속한 구간의 분당 금액을 기준 시각 이후의 **전체 지각 시간**에 적용한다.

| 도착 시각 | 계산 | 지각비 |
|---|---:|---:|
| 10:32 | 2분 × 100원 | 200원 |
| 10:42 | 12분 × 300원 | 3,600원 |
| 10:52 | 22분 × 500원 | 11,000원 |
| 11:12 | 42분 × 1,000원 | 42,000원 |

### 7.4 설정 표현

정산 모달에서는 기준 시각을 기준으로 구간을 다음과 같이 표시한다.

- 1~10분 지각: 전체 지각 분 × 100원
- 11~20분 지각: 전체 지각 분 × 300원
- 21~30분 지각: 전체 지각 분 × 500원
- 31분 이상 지각: 전체 지각 분 × 1,000원

기준 시각과 각 구간의 종료 시점 및 금액은 정산 확정 전에 수정할 수 있다.

## 8. 일요일 지각·결석 관리

### 8.1 운영 방식

- 일요일에는 QR을 사용하지 않는다.
- 담당자가 일요일 출결 체크 페이지에서 직접 기록한다.
- 기본적으로 현역 찬양팀원만 표시한다.

### 8.2 출결 상태와 금액

| 상태 | 금액 |
|---|---:|
| 정상 | 0원 |
| 지각 | 3,000원 |
| 결석 | 3,000원 |

### 8.3 체크 페이지 기능

- 일요일 날짜 선택
- 현역 팀원 목록 표시
- 팀원별 정상·지각·결석 선택
- 팀원별 메모 입력
- 일괄 저장
- 저장 전 지각·결석 인원 및 예상 금액 요약

승인된 사유가 있는 팀원은 목록에 계속 표시하되 입력을 비활성화하고 `사유 승인` 배지를 표시한다. 승인된 팀원에게는 일요일 지각·결석 금액을 부과하지 않는다.

## 9. 지각·결석 사유 신청

### 9.1 사용자 달력

- 달력에서 토요일과 일요일만 활성화한다.
- 활성화된 날짜를 누르면 사유 제출 모달을 표시한다.
- 신청 가능한 과거·미래 날짜 범위는 관리자 설정으로 제한할 수 있다.

### 9.2 신청 항목

- 대상 날짜
- 지각 또는 결석
- 사유
- 예상 도착 시각 또는 추가 메모

### 9.3 신청 상태

- 승인 대기
- 승인
- 반려
- 취소

승인 대기 상태에서는 사용자가 신청을 취소할 수 있다. 승인 또는 반려 이후에는 직접 수정할 수 없다.

### 9.4 관리자 승인

- 기간 필터
- 신청 상태 필터
- 신청자 검색
- 대상 날짜 및 요일
- 지각·결석 구분
- 신청 사유
- 승인 또는 반려
- 반려 사유 입력
- 처리 관리자 및 처리 시각 저장

### 9.5 승인 결과 반영

- 토요일: 승인된 사용자는 QR을 스캔하지 않는 운영 방식이므로 별도의 자동 면제 기록을 생성하지 않는다.
- 일요일: 승인된 사용자를 체크 목록에서 비활성화하고 0원으로 처리한다.
- 정산 확정 후에는 사유 승인 여부를 변경하여 정산 금액을 수정할 수 없다.

## 10. 통합 출결 기록

토요일 QR 기록과 일요일 수동 기록은 같은 출결 기록 구조에 저장하며 모임 유형과 출결 상태로 구분한다.

### 10.1 주요 항목

- 기록 ID
- 날짜
- 요일
- 모임 유형: 토요일 / 일요일
- 팀원
- 출결 상태: 지각 / 결석
- 기준 시각
- 도착 시각
- 지각 시간
- 기록 방식: QR / 관리자 수동
- 계산 금액
- 정산 상태
- 메모
- 생성 시각
- 수정 시각

토요일 기록은 기본적으로 `지각`만 발생한다. 일요일 기록은 `지각`과 `결석`을 구분하지만 두 상태 모두 기본 금액은 3,000원이다.

### 10.2 관리자 테이블 컬럼

- 선택 체크박스
- 날짜 및 요일
- 토요일·일요일 구분
- 팀원
- 지각·결석 구분
- 기준 시각
- 도착 시각
- 지각 시간
- 기록 방식
- 계산 금액
- 정산 상태
- 메모

### 10.3 필터

- 시작일과 종료일
- 토요일 / 일요일
- 지각 / 결석
- 팀원
- 활동 상태
- 미정산 / 정산 요청 / 정산 완료

기간을 선택하면 해당 기간의 미정산 기록을 자동으로 선택한다. 관리자는 정산을 열기 전에 개별 기록을 선택하거나 선택 해제할 수 있다.

## 11. 정산 생성

### 11.1 정산 흐름

1. 관리자가 통합 출결 기록에서 시작일과 종료일을 지정한다.
2. 기간 내 미정산 기록이 자동 선택된다.
3. 관리자가 포함할 기록을 최종 선택한다.
4. `정산` 버튼을 누른다.
5. 정산 설정 및 미리보기 모달을 표시한다.
6. 토요일 기준 시각과 과금 구간을 확인한다.
7. 일요일 지각·결석 금액을 확인한다.
8. 사람별 상세와 전체 총합을 검토한다.
9. 최종 확인 후 정산 요청을 확정한다.

### 11.2 정산 모달 기본값

- 토요일 기준 시각: 10:30
- 1~10분: 분당 100원
- 11~20분: 분당 300원
- 21~30분: 분당 500원
- 31분 이상: 분당 1,000원
- 일요일 지각: 3,000원
- 일요일 결석: 3,000원

모든 값은 정산을 확정하기 전까지만 수정할 수 있다.

### 11.3 정산 미리보기

- 정산 기간
- 선택된 전체 기록 수
- 토요일 지각 기록 수
- 일요일 지각 기록 수
- 일요일 결석 기록 수
- 사람별 포함 기록
- 사람별 청구 금액
- 전체 청구 금액
- 적용할 과금 규칙

### 11.4 검증 규칙

- 선택된 기록이 없으면 정산을 생성할 수 없다.
- 이미 다른 정산에 포함된 기록은 선택할 수 없다.
- 정산 기간 밖의 기록이 포함되면 확정할 수 없다.
- 정산 확정 시 사용한 규칙을 정산 데이터에 스냅샷으로 저장한다.
- 이후 기본 과금 규칙이 바뀌어도 과거 정산에는 영향을 주지 않는다.

## 12. 정산 확정 및 재정산 금지

정산 요청이 확정되는 순간 포함 기록과 계산 결과를 잠근다.

### 12.1 확정 후 금지되는 작업

- 정산 기간 수정
- 포함 기록 추가 또는 제외
- 토요일 과금 규칙 수정
- 일요일 지각·결석 금액 수정
- 사람별 청구 금액 수정
- 포함된 출결 기록의 시각·상태·금액 수정
- 동일한 출결 기록을 다른 정산에 중복 포함
- 정산 재계산 또는 재정산

### 12.2 최종 확인 문구

```text
정산을 확정하면 포함 기록과 청구 금액을 수정하거나 재정산할 수 없습니다.
기간, 대상 기록, 적용 규칙 및 총액을 확인했습니까?
```

사용자가 명시적으로 확인한 후에만 정산을 확정한다.

## 13. 정산 요청 상세 및 납부 처리

### 13.1 상단 정보

- 정산명
- 정산 기간
- 생성일
- 정산 상태
- 적용된 토요일 과금 규칙
- 적용된 일요일 지각·결석 금액
- 전체 청구 금액
- 전체 납부 금액
- 전체 미납 금액

### 13.2 사람별 정산 테이블

| 팀원 | 토요일 | 일요일 지각 | 일요일 결석 | 총 청구액 | 납부 상태 |
|---|---:|---:|---:|---:|---|
| 김찬양 | 3,600원 | 3,000원 | 0원 | 6,600원 | 미납 |
| 이사랑 | 200원 | 0원 | 3,000원 | 3,200원 | 납부 완료 |

테이블 하단에는 사람별 금액의 전체 총합을 표시한다.

### 13.3 납부 상태

- 미납
- 납부 완료

관리자는 사람별로 납부 완료를 처리한다. 납부 처리는 계산 수정이 아니므로 정산 확정 후에도 가능하다. 모든 대상자가 납부 완료되면 정산 전체를 `정산 완료` 상태로 변경할 수 있다.

## 14. 카카오톡 공지 문구

정산 상세 페이지에서 찬양팀 카카오톡방에 공유할 문구를 자동 생성한다.

```text
[찬양팀 지각비 정산 안내]

정산 기간: 2026.03.28 ~ 2026.04.04

3.28 토
11:01(31분) 종민 31,000원

3.29 일
정민, 태균 (각 3,000원)

4.04 토
10:36(6분) 지혜 600원
10:38(8분) 양래 800원
11:10(40분) 민엽 40,000원

각자 금액 확인 후 납부 부탁드립니다.
```

### 14.1 기능

- 정산 기록을 날짜 및 요일 순서로 묶어서 표시
- 토요일은 `도착 시각(지각 시간) 이름 금액` 형식으로 한 명씩 표시
- 일요일은 지각·결석 대상자를 한 줄로 묶고 `이름, 이름 (각 3,000원)` 형식으로 표시
- 0원 기록 제외
- 정산 기간 표시
- 공지 문구에는 전체 총합을 표시하지 않음
- `공지 문구 복사` 버튼
- 복사 성공 안내 표시
- 설정된 계좌 정보와 추가 안내 문구 삽입 가능

## 15. 공개 통계·랭킹

통계와 랭킹은 관리자 CMS가 아닌 공개 영역에 제공한다. 별도의 로그인이나 사용자 인증 없이 접근할 수 있다.

### 15.1 공개 통계

- 전체 누적 지각비
- 올해 누적 지각비
- 이번 달 지각비
- 기간별 지각비 추이
- 토요일 지각 횟수
- 일요일 지각 횟수
- 일요일 결석 횟수
- 토요일·일요일 금액 비율
- 최근 완료된 정산 기간

### 15.2 공개 랭킹

- 누적 지각비 순위
- 지각·결석 총횟수 순위
- 토요일 지각비 순위
- 일요일 지각·결석 금액 순위
- 기간별 랭킹
- 현역 팀원만 보기 / 전체 팀원 보기

### 15.3 공개 데이터 기준

- 공식 통계와 랭킹에는 `정산 완료`된 기록만 포함한다.
- 미정산 또는 정산 요청 상태의 기록은 공개 통계에 포함하지 않는다.
- 졸업, 군 복무, 휴식 상태로 변경된 팀원의 과거 기록도 보존한다.
- 기본 랭킹은 현역 팀원만 표시하고 사용자가 전체 팀원 보기로 전환할 수 있다.
- 동점일 경우 공동 순위로 표시한다.

### 15.4 공개 범위 및 개인정보

- 기본 공개 정보는 이름, 활동 상태, 지각·결석 횟수 및 지각비 금액으로 제한한다.
- 연락처, 인증 정보, OTP, 메모, 사유 내용은 절대 공개하지 않는다.
- 사용자 이름 전체 공개가 부담되는 경우 관리자가 공개용 표시 이름 또는 이름 마스킹을 설정할 수 있도록 확장 가능하다.

## 16. 관리자 대시보드

공개 통계 페이지와 별도로, 관리자 대시보드에는 운영에 필요한 비공개 지표를 제공한다.

- 미정산 기록 수
- 정산 요청 수
- 미납 인원 및 미납 금액
- 승인 대기 중인 사유 신청 수
- 최근 토요일 QR 기록
- 최근 일요일 출결 기록
- 최근 정산 목록
- 인증 오류 및 관리자 조치가 필요한 항목

미납 상태나 승인 대기 신청처럼 운영상 민감한 정보는 공개 통계 페이지에 표시하지 않는다.

## 19. 보안 및 운영 요구사항

- 관리자 CMS의 모든 페이지는 관리자 인증 후에만 접근할 수 있어야 한다.
- 공개 페이지에서는 관리자 API와 개인정보에 접근할 수 없어야 한다.
- OTP 비밀키, 인증 토큰 및 관리자 비밀번호는 원문으로 저장하지 않는다.
- 로그인과 OTP 인증에는 시도 횟수 제한을 적용한다.
- 출결 등록과 정산 확정 API는 중복 요청에 안전해야 한다.
- 모든 금액 계산은 클라이언트가 아닌 서버에서 수행한다.
- 모든 시각 기록은 서버 기준 시간대에 따라 처리한다.
- 서비스 기본 시간대는 `Asia/Seoul`로 한다.
- 정산 확정, 기록 수정, 사유 승인 및 납부 완료에는 감사 로그를 남긴다.
- 공개 통계 API에는 연락처, 사유, 메모, OTP 및 인증 토큰을 포함하지 않는다.

공용 QR URL은 다른 사람에게 공유될 수 있으므로 QR 스캔만으로 실제 장소 방문을 완전히 증명할 수는 없다. 필요해지면 향후 QR 토큰 주기적 변경, 관리자 당일 활성화 또는 네트워크 제한 등을 추가할 수 있다.

## 20. 주요 예외 상황

### 20.1 QR 중복 스캔

- 기존 최초 기록을 유지한다.
- 사용자에게 기존 기록 시각을 표시한다.

### 20.2 OTP 만료

- 인증을 실패 처리한다.
- 새로 생성된 현재 OTP를 입력하도록 안내한다.

### 20.3 비활동 팀원의 QR 접근

- 새로운 기록을 만들지 않는다.
- 관리자에게 활동 상태 확인을 요청하도록 안내한다.

### 20.4 정산된 기록 수정 시도

- 수정 요청을 차단한다.
- `확정된 정산에 포함된 기록은 수정할 수 없습니다`라고 표시한다.

### 20.5 승인 사유가 있는 일요일 팀원

- 목록에는 표시한다.
- 상태 입력은 비활성화한다.
- `사유 승인` 배지와 0원을 표시한다.

### 20.6 네트워크 오류 중 QR 기록

- 기록 완료 응답을 받기 전까지 완료로 표시하지 않는다.
- 재시도하더라도 날짜·사용자 기준 중복 방지 규칙으로 하나의 기록만 생성한다.

## 22. 핵심 사용자 흐름 요약

### 22.1 토요일 지각

```text
지각자
→ 벽면 공용 QR 스캔
→ 인증 상태 확인
→ 최초 접속이면 사용자 선택 및 6자리 OTP 인증
→ 지각 기록 페이지
→ 서버 접속 시각 저장
→ 기록 완료
```

### 22.2 일요일 출결

```text
담당자
→ 일요일 날짜 선택
→ 현역 팀원 목록 확인
→ 지각 또는 결석 체크
→ 각각 3,000원 기록
→ 일괄 저장
```

### 22.3 사유 신청

```text
팀원
→ 토·일요일 달력에서 날짜 선택
→ 지각 또는 결석 사유 제출
→ 관리자 승인 또는 반려
→ 승인 시 일요일 체크 대상 비활성화
→ 토요일 승인자는 QR을 스캔하지 않음
```

### 22.4 정산

```text
관리자
→ 정산 기간 선택
→ 미정산 기록 자동 선택
→ 대상 기록과 과금 규칙 확인
→ 사람별 금액 및 총합 미리보기
→ 정산 확정
→ 기록과 금액 잠금
→ 카카오톡 공지 복사
→ 사람별 납부 완료 처리
→ 전체 정산 완료
→ 공개 통계·랭킹에 반영
```

## 23. 완료 조건

다음 조건을 모두 충족하면 MVP가 요구사항을 충족한 것으로 본다.

- 미인증 사용자가 QR을 스캔하면 OTP 인증 후 기록 페이지로 복귀한다.
- 인증된 사용자가 QR을 스캔하면 서버 시각으로 토요일 지각이 한 번만 기록된다.
- 토요일 지각비가 도착 구간의 분당 금액을 전체 지각 분에 적용하여 계산된다.
- 관리자가 일요일 지각과 결석을 각각 3,000원으로 기록할 수 있다.
- 승인된 사유가 있는 팀원은 일요일 체크 화면에서 비활성화된다.
- 관리자가 기간별 미정산 기록을 선택하여 정산 미리보기를 확인할 수 있다.
- 확정된 정산과 포함 기록은 수정하거나 재정산할 수 없다.
- 정산 상세에서 사람별 금액, 전체 총합 및 납부 상태를 확인할 수 있다.
- 카카오톡 공지 문구를 버튼으로 복사할 수 있다.
- 정산 완료 데이터가 로그인 없는 공개 통계·랭킹에 반영된다.
- 공개 영역에서 개인정보, 사유, OTP 및 인증 정보가 노출되지 않는다.
